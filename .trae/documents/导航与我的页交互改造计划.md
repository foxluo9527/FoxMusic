# 客户端导航与「我的」页交互改造实施计划

> 范围：KMP 双端（Android + iOS）。共享层 `commonMain` 改动两端同时生效；导航外壳（Android `NavGraph` / iOS SwiftUI）两端各改一次。
> 目标：把「我的」改成个人主页风格 + 音乐/动态双 tab；底部栏去掉「消息」、中央加音流圆钮；全部主 Tab 顶部加三横抽屉入口；消息/AI 助手/常用设置入口迁入抽屉。

## Context（为什么改）

现状：底部 5 个 Tab（首页/发现/社区/**消息**/我的）由 Android `AppDestinations` 与 iOS `ContentView` 的 `TabView` 各自维护；「我的」页是一个卡片头 + 4 个 tab（我的/歌单/专辑/艺术家）的设置型列表；AI 助手入口在首页搜索框里；音流模式是独立路由无入口；消息是独立 Tab。

用户希望对齐网易云的交互：个人主页化「我的」、抽屉式全局入口、中央圆钮承载音流、把低频 Tab（消息）与常用设置收进抽屉，信息层级更清晰。本次改造同时涉及共享 UI 与两端导航外壳，必须两端一致。

## 目标结构（改完后的信息架构）

- **底部 Tab（两端一致）**：`首页` · `发现` · `[音流]`（中央圆形突起按钮）· `社区` · `我的`。移除「消息」Tab。
  - 参考图：中心圆钮 + 两侧各 2 个普通 Tab。
- **左侧抽屉**（四个主 Tab 顶部左上角三横图标触发，仿网易云侧边栏）：
  - 顶部：头像 + 昵称（点击 → 个人主页）
  - 菜单：`我的消息`（带未读角标）、`AI 音乐助手`、`资料编辑`、`定时关闭`、`下载管理`、`主题设置`、`曲库管理`
  - 底部：一个「设置」按钮
- **「我的」页**：个人主页样式头部（封面背景 + 头像 + 昵称 + 签名 + 统计），顶层两个 tab：`音乐` / `动态`。
  - `音乐` 下两个子 tab：`创建` / `收藏`。
    - `创建`：历史播放、我喜欢的音乐（收藏单曲）、创建的歌单列表（含「创建歌单」入口）。下载管理移出。
    - `收藏`：单列表分区 —— 歌单 / 专辑 / 艺术家，每区最多展示 N 条（建议 3），超出显示「更多」项，点击进入对应详情页。
  - `动态`：自己的动态（帖子）列表（复用 `UserHomeViewModel.postsPagingFlow`）。
- **消息**：不再是 Tab，改为抽屉入口进入的二级页面（Android 走非 Tab 路由且带返回；iOS 以模态承载 `MessagesTabView`）。

## 分阶段实施

每个阶段独立编译、独立验证，避免一次性改动过大。

### 阶段 1：共享层 UI（commonMain / core:ui）

**1.1 主 Tab 顶部统一「三横 + 居中标题」**
- 在 `core:ui` 新增共享组件 `TabPageTopBar`（左：三横 `Menu` 图标按钮；中：标题，`fontWeight = Normal`，居中；右：可选的右侧图标插槽如搜索）。
- 改造各内容 composable，新增参数 `onOpenDrawer: () -> Unit = {}`：
  - `HomeContent`：`HomeBrandHero` 左侧加三横；标题居中不粗（保留品牌/标题文案）；**移除**搜索框内的 AI 助手 pill（`onAssistantClick` 参数保留但不再渲染 pill）。
  - `DiscoverContent`：`发现` 标题改为 `TabPageTopBar`。
  - `CommunityPlazaContent`：顶部加 `TabPageTopBar`（标题「社区」）。
  - `ProfileContent`：见 1.3（标题并入个人主页头部）。

**1.2 共享抽屉内容（Android 复用；iOS 走原生 SwiftUI，见阶段 3）**
- 在 `core:ui` 新增 `MineDrawerContent` composable（纯 UI，回调驱动）：
  - 头部：头像 + 昵称（点击回调）
  - 列表：我的消息（角标）、AI 音乐助手、资料编辑、定时关闭、下载管理、主题设置、曲库管理
  - 底部：单个「设置」按钮
  - 回调：`onMessagesClick/onAssistantClick/onEditProfileClick/onSleepTimerClick/onDownloadsClick/onThemeClick/onManageLibraryClick/onSettingsClick/onProfileClick`，`isLogin` 控制游客态。

**1.3 「我的」页重构（`ProfileContent.kt` → 个人主页样式）**
- 头部改为个人主页样式：封面背景（无则渐变占位）+ 头像 + 昵称 + 签名 + 统计行（听歌时长取 `state.listeningStats.totalDurationMinutes`；关注/粉丝等若数据缺失则先留位/省略，见「数据缺口」）。
- 顶层 tab：`音乐` / `动态`（新增 `ProfileTopTabs = listOf("音乐","动态")`，沿用现有 `ProfileTab` 指示条样式）。
- `音乐` → 子 tab 行 `创建` / `收藏`。
  - `创建`：`历史播放` 行、`我喜欢的音乐` 行（`onIntent(ProfileIntent.OnFavoriteTracksClick)`）、`SectionHeader("我的歌单", moreText="创建歌单")` + `ProfilePlaylistListItem` 列表（保留现有更多菜单/删除确认逻辑）。**删去「下载管理」行**。
  - `收藏`：三个分区 `歌单` / `专辑` / `艺术家`，每区最多 3 条 + 不足/超出时显示「更多」行；「更多」回调 `onMoreFavoritePlaylists / onMoreFavoriteAlbums / onMoreFavoriteArtists`。复用 `ProfilePlaylistListItem` / `AlbumListItem` / `ArtistListItem`。
- `动态`：`PostCard` 列表（由宿主注入 `LazyPagingItems<Post>` 与 `currentUserId`），复用 `UserHomeScreen` 的 `UserHomePostsTab` 写法。
- 游客态：保留 `ProfileGuestLoginPrompt`（头部用占位昵称）。

**1.4 收藏详情页（共享）**
- 新增 `FavoriteCollectionDetailContent`（`feature/profile` commonMain 或 `core:ui`）：通用顶部返回栏 + 标题 + 下方 `LazyColumn` 全量列表；入参 `title`、`type`（playlists/albums/artists）、数据列表、`onBack`、以及点击回调。复用 1.3 中保留的列表项样式代码。

**1.5 音流共享化（供两端复用）**
- 将 `StreamScreen.kt` 的 `StreamContent` / `StreamCard` 抽成可在 `commonMain` 或 `iosShared` 复用的 composable；`AsyncImage` 换成 `core:ui` 的 `CachedImage`（跨端），`detectTapGestures` 换 `clickable`。iOS 侧在 `iosShared` 提供 `FoxStreamScreen`（复用 `StreamViewModel` 对应逻辑，数据走 `FoxMusicApi` 的 highlight/stream 接口）。

**1.6 消息二级化（共享层）**
- `MessagesContent` 增加 `showBackButton`/顶部返回支持（已在部分路径支持），消息 Tab 场景改为「二级页」调用（顶部 `TabPageTopBar` 左侧返回 + 标题「我的消息」）。

### 阶段 3：iOS 导航外壳（SwiftUI）

## 数据缺口与需新增的接口/状态

- **头部统计**：`User` 模型无「关注/粉丝/等级」字段（[User.kt](file:///Users/luofulin/AndroidStudioProjects/FoxMusic/core/model/src/commonMain/kotlin/com/fox/music/core/model/user/User.kt#L7-L22)；`UserProfile` 有 `friendCount/playlistCount/favoriteCount`，[UserProfile](file:///Users/luofulin/AndroidStudioProjects/FoxMusic/core/model/src/commonMain/kotlin/com/fox/music/core/model/user/User.kt#L32-L51)）。听歌时长可用 `ListeningStats.totalDurationMinutes`。
  - 方案：优先取 `UserProfile`（关注信息 → `friendCount`，歌单数 → `playlistCount`），等级暂不展示或后续接口补齐。实施时确认是否有「获取我的资料」用例（`GetUserProfileUseCase`）。
- **收藏分区「更多」**：需在 `ProfileState` 暴露收藏总数（已有 `favoritePlaylistTotal/favoriteAlbumTotal/favoriteArtistTotal`）；详情页数据用现有 `GetFavoritesUseCase.getPlaylists/getAlbums/getArtists` 分页。
- **动态分页**：`UserHomeViewModel.postsPagingFlow` 已存在（仅 android）。移动到 `feature/profile` commonMain 或让 iOS 复用同等分页源。
- **音流数据**：Android 用 `feature/stream` 的 `StreamViewModel`（android）；iOS 需 `iosShared` 侧对应实现（highlight/stream 接口）。

## 验证方式（端到端）

1. **Android 编译**：`./gradlew :app:assembleDebug`（或 IDE 构建）通过。
2. **iOS 构建**：构建 `iosShared` framework + Xcode 编译 `iosApp` 通过（`xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp -destination 'platform=iOS Simulator,name=iPhone 16'`）。
3. **Android 手动/自动化**：底部栏为 首页/发现/[音流]/社区/我的；四主 Tab 左上三横可开抽屉；抽屉各项跳转正确；「我的」页头部为个人主页样式、音乐(创建/收藏)/动态 可用；收藏「更多」进详情并能返回；音流圆钮进入音流页。
4. **iOS 手动/自动化**：同 Android 逐项验证；重点验证自定义底部栏圆钮命中、抽屉动画与模态导航、消息经抽屉打开后返回、迷你条不遮挡。
5. **回归点**：迷你播放条在两端不遮挡底部栏；通知横幅跳转消息仍可用；游客态抽屉与「我的」页显示正确；主题切换后顶栏/底部栏/抽屉配色即时跟随。

## 假设（如与实际意图不符请指出）

1. 「创建」子 tab = 历史播放 + 我喜欢的音乐 + 创建的歌单列表（不含下载管理）；下载管理只保留在抽屉。
2. 首页顶栏居中标题保留品牌文案「FoxMusic」，不改为「首页」。
3. 抽屉里「主题设置」复用现有设置页的主题/深色项（必要时抽取独立 `ThemeSettingsView`）。
4. 头部「关注/粉丝/等级」在数据缺口下先展示可得项（关注≈好友数、听歌时长），等级暂缺省。
5. iOS 底部栏由 SwiftUI 原生重建（放弃系统 `TabView` 外观），以支持中央突起圆钮。
